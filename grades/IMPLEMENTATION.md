# رصد درجات برنامج يسير — تحديث الصلاحيات والواجهة

## ما تم رفعه إلى GitHub
- استخدام شعار الوزارة الأبيض الأصلي من مصادر المشروع داخل الترويسة، مع النص الإداري واسم المدرسة والتدرج المعتمد.
- إظهار اسم المادة ومجموعة الفصول بوضوح في شاشة الطلاب، وإظهار المادة في شاشة الطالب.
- لوحة المنسق: إضافة الطالب (الاسم الأول والأخير + الفصل + المواد)، تعديل بياناته، حذفه من عرض المعاينة.
- لوحة المنسق: إنشاء رموز دخول مستقلة لكل مجموعة فصول في المادة، وتعديل الإسناد أو إلغاء المجموعة.
- التحقق على مستوى المعاينة من ظهور طلاب الفصول والمواد المسموح بها لكل رمز.
- فتح أو إغلاق تقييم واحد، فترة كاملة، جميع فترات المادة، أو جميع المواد والفترات.
- تصدير CSV تجريبي متوافق مع Excel.
- إضافة مصدر لخدمة Firebase callable backend وقواعد Firestore الافتراضية التي تمنع القراءة والكتابة المباشرتين.

## حدود النسخة المنشورة الآن
**الواجهة على GitHub Pages ما زالت نسخة عرض تجريبية، وليست نظامًا إنتاجيًا.**
- يُعرض منسق تجريبي ورموز تجريبية داخل HTML، ولا تشكل أي حماية لبيانات حقيقية.
- البيانات والدرجات والتحكم في الإغلاق والإسناد محلية مؤقتة في ذاكرة الصفحة، وتختفي عند إعادة التحميل.
- لا توجد بيانات حقيقية محفوظة في GitHub. لا تستخدم هذه النسخة لرصد درجات طلاب حقيقيين.
- ملف تصدير المعاينة CSV وليس XLSX، ولا يوجد مزامنة مع نور.

## متطلبات التشغيل الحقيقي
1. الحصول على موافقة الجهة المختصة لحفظ البيانات التعليمية لدى الخدمة السحابية المختارة.
2. تجهيز مشروع Firebase منفصل مناسب من حيث الموقع الجغرافي والضوابط النظامية.
3. مراجعة واختبار ملفات `grades/backend/functions/index.js` وقواعد `grades/backend/firestore.rules` في بيئة تجريبية.
4. تفعيل `YASIR_ADMIN_PIN` و`YASIR_PIN_PEPPER` كـ Secret Manager secrets، لا في GitHub أو HTML.
5. نشر Cloud Functions وFirestore rules، ثم ربط واجهة GitHub Pages بالمصادقة وعمليات API الخلفية.
6. اختبار الصلاحيات فعليًا: محاولة الوصول لفصل غير مسند، فتح مادة أخرى، تعديل تقييم مغلق، إبطال رمز قديم، مراجعة سجل العمليات.
7. اختبار الاستجابة على الجوال، وصولية العناصر، وتصدير Excel قبل استخدامه.
